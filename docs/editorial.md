# 技术文章编辑约定

参考 [Humanizer](https://github.com/blader/humanizer/blob/main/SKILL.md) 和 [technical-writing](https://github.com/ericrisco/rsc-harness/blob/main/skills/technical-writing/SKILL.md)。使用其编辑方法，不复制示例，也不为文章补造作者经历。

- 标题直接说明技术对象与主题，开篇讲清对象是什么。定义、核心原理和关键术语不能被案例代替。
- 每篇按自身原理组织，不套统一节序：交互策略展开行动与观察，协议展开角色与消息，数学主题展开公式与变量，评测主题展开对象、判据与统计。案例用于说明相应原理，位置由内容决定。
- 每段增加新信息。删掉泛泛的价值判断、重复小结、强行排比，以及“本文将”“先抓住一个判断”等写作提示。
- 图解释文字难以直接表现的关系：时序、状态变化、证据覆盖、分母、冲突或职责。图与相应解释相邻；不能把同一组标签换颜色当作新图。
- 论文原图保留归属和原文链接；改绘标明依据。图上的数字、版本和结论必须与正文一致。
- 案例交代输入、过程中的关键数据、输出和失败条件。教学数据标记一次；实际跑过的结果说明样本范围。不能把伪代码、预期行为或漂亮截图写成实测结果。
- 代码标明语言、运行条件及预期输出。可运行代码实际验证；伪代码明确其抽象边界。高亮由构建生成，图支持放大。
- 手记保留可核实的制作事实和观察。没有原始记录的情绪、顿悟、个人回忆不代写。
- 完成后对照原始资料核事实，再在浏览器检查桌面、手机、图中文字和代码。自动检查不能代替阅读。
