# 在聊天里发布动态和文章

用户已选择在当前聊天中提供内容并请求发布，网站公开页面只负责阅读。只有明确要求发布的内容才上线；讨论、草稿和内部笔记不作为动态。

## 文字动态

在 `data/updates.json` 添加唯一 `id`、`date`、`publishedAt` 和 `content`。`content` 是纯文本，保留用户的段落和换行，首页完整显示。可选 `image` / `imageAlt` 使用 `assets/images/` 中的图片。动态不需要标题或独立文章页。

## 长文章

在 `data/posts.json` 添加文章：唯一 `id`、`date`、`publishedAt`、`title`、`summary`、`category`、`tags`、`sections`、`links`，以及可选 `image` / `imageAlt`。沿用现有结构。首页只显示标题和摘要，卡片点击进入 `posts/<id>.html` 阅读全文。摘要应来自用户内容，不虚构经历、观点或项目成果。

`inFeed: false` 仅保留旧文章链接而不在首页重复展示。原站点介绍已改为普通文字动态，旧文章 URL 继续可用。不要再添加单独的「想法」栏目或突出展示该介绍。

## 视觉与结构

用户已选择暖色纸感风格：米白底、柔和墨色、舒展留白。首页保持短动态与长文章摘要混排，不仿制社交平台的头像框线布局。首页、作品集、新闻及全部详情页共用 `src/page.template.html` 和 `assets/styles.css`；修改设计时应覆盖全站，不另起一套单页导航或配色。

## 时间与发布

两种内容按日期及真实发布时间统一倒序。`date` 使用用户所在的 `America/Los_Angeles` 日期，`publishedAt` 使用包含时区的真实 ISO 时间。同日使用时间排序；旧内容没有精确时间时保持已有顺序，不编造历史时刻。既有动态修改时保留 ID 与原发布时间。

1. 检查工作区和远程状态，保留用户已有改动；仅在无冲突时快进到远程。
2. 按用户明确指定的类型新增或修改内容。若要求修改或删除既有内容，先定位对应 ID。
3. 运行 `npm run build`、`npm run check` 和 `git diff --check`；查看手机排版、文字完整性与文章入口。
4. 仅提交本次内容及生成页面，正常推送 `main`，不强推、不覆盖他人提交。
5. 等待对应 GitHub Pages 提交构建成功，核对受影响的公开页面，再给用户发布链接。动态链接使用 `https://be1human.github.io/portfolio/#status-<id>`。

网站不需要访客登录，也没有公开写入接口。发布借助当前聊天已有的 GitHub 连接完成。新闻同步独立运行，不应因为发布动态而修改资讯源或同步配置。
